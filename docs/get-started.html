Static export workflow

Export WordPress as a static snapshot.

PortPress crawls public URLs, writes HTML files, copies frontend assets, and rewrites same-site links so a WordPress site can be previewed, zipped, and hosted on static infrastructure.

See export demos
1. Discover URLsStart from public WordPress URLs that should become static pages.
2. Render pagesVisit those URLs through WordPress or internal rendering.
3. Package outputRewrite same-site links, copy assets, and download a ZIP or folder.

Browser Playground

Fastest way to see the export workflow. The PortPress demo installs both tools, seeds sample content, and opens a guide that links to the static export screen.

Regular WordPress admin

Use this for a real site when you want one-click ZIP downloads and persistent media.

cp -R static-site-generator /path/to/wordpress/wp-content/plugins/

Activate StillPress, then open Tools -> StillPress. This is the current implementation name for the static export workflow.

Run repeatable exports

Use Playground CLI for disposable WordPress runtimes, or WP-CLI from a real WordPress root for scheduled or repeatable static builds.

mkdir -p ./static-site-output
npx @wp-playground/cli@latest run-blueprint \
	--mount=./static-site-generator:/wordpress/wp-content/plugins/static-site-generator \
	--mount=./static-site-output:/exports \
	--blueprint=./blueprints/static-site-generator-cli-export.json

The generated ZIP is written to ./static-site-output/static-site.zip.

wp plugin activate static-site-generator
wp static-site export --output=./static-site.zip --fetch-mode=auto
wp static-site export --output-dir=./static-site --fetch-mode=auto

Useful flags include --url-mode=relative, --url-mode=root, --url-mode=absolute, --fetch-mode=internal, --generate-sitemap, --generate-robots, and --report.

Preview before hosting

After extracting the ZIP, run a local HTTP server from the extracted folder:

python3 -m http.server 8080

Then open http://localhost:8080/. Direct file:// previews are useful for basic HTML and CSS checks, but local HTTP is closer to production hosting.
